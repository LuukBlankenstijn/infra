# NetBird

The NetBird control plane for `netbird.luukblankenstijn.nl` runs in the cluster
from raw manifests in `flux/50_apps/netbird` (namespace `netbird`):

| Deployment | Image | Role |
| --- | --- | --- |
| `server` | `netbirdio/netbird-server` | management, signal and relay in one process, `strategy: Recreate` |
| `dashboard` | `netbirdio/dashboard` | web UI |
| `reverse-proxy` | `netbirdio/reverse-proxy` | see [NetBird reverse proxy](reverse-proxy.md) |

The account configuration (groups, policies, DNS, users, the Authentik
connector) is `terraform/60_netbird-config`.

## Routes

| Path on `netbird.luukblankenstijn.nl` | Backend |
| --- | --- |
| `/relay`, `/ws-proxy`, `/oauth2`, `/api` | `netbird-service:80` |
| `/signalexchange.SignalExchange`, `/management.ManagementService`, `/management.ProxyService` | `netbird-service:81`, `scheme: h2c` (gRPC) |
| everything else | `dashboard:80` |

Port 81 of `netbird-service` targets the same container port 80 with
`appProtocol: kubernetes.io/h2c`. The relay runs over WebSocket on 443; STUN is
coturn on the edge, `stun:hertzner.luukblankenstijn.nl:3478` (see
[Edge](edge.md#services-on-the-host)). The server trusts `X-Forwarded-*` from
`10.42.0.0/16` (`reverseProxy.trustedHTTPProxies`).

## State

| What | Where |
| --- | --- |
| Accounts, peers, policies | Postgres `netbird` (`store`) |
| Activity events | Postgres `netbird_events` (`activityStore`) |
| Embedded IdP | Postgres `netbird_idp` (`authStore`) |
| Data directory `/var/lib/netbird` | PVC `netbird-data`, 1 Gi, `longhorn` |
| `config.yaml` | Secret `netbird-config`, rendered by an ExternalSecret |

The ExternalSecret `netbird-config` builds `config.yaml` from a template:
`store_encryption_key`, `session_cookie_key` and `auth_secret` from OpenBao
`secret/netbird/server` (generated by `40_openbao-config`), and the three
Postgres DSNs from `postgres/netbird/{netbird,netbird_events,netbird_idp}`
(`40_databases`), all with `sslmode=verify-full`.

The store encryption key encrypts fields in the `netbird` database; the database
is unreadable without that exact key, so restoring one means restoring the
other.

Image bumps are one-way: the server migrates the database schema on start.
Renovate never automerges `netbirdio/*` images.

## Login

The issuer is NetBird's embedded IdP at `https://netbird.luukblankenstijn.nl/oauth2`.
Two ways to log in:

- **Authentik.** `60_netbird-config` attaches Authentik as the OIDC connector
  `netbird_identity_provider.authentik`. The client (`client_id` `netbird`,
  redirect URIs `/oauth2/callback` and `/oauth2/logout/callback`) is created by
  `50_authentik-config`, which writes `client_id`, `client_secret` and `issuer`
  to OpenBao `authentik/netbird/netbird`; `60_netbird-config` reads them from
  there. A policy binding limits the Authentik application to group
  `infra-admins`; nobody else sees it or can log in.
- **Local owner**, break-glass, credentials in `secrets/netbird.yaml`
  (`owner_email`, `owner_password`). Local auth stays
  enabled for it (`localAuthDisabled: false`).

The owner's personal access token, minted by `/api/setup`, is `api_token` in
`secrets/netbird.yaml`. It is the `netbird` provider token of
`60_netbird-config` and, through OpenBao `secret/netbird/operator`, the
netbird-operator API key.

SSO users join the account whose `domain` is the single-account domain
`netbird.selfhosted` and that is marked `is_domain_primary_account`. The account
`/api/setup` creates has neither, so on a fresh store, right after `/api/setup`
and before the first Authentik login, mark it:

```sh
kubectl -n netbird scale deploy server --replicas=0
kubectl -n postgres exec postgres-1 -c postgres -- psql -U postgres -d netbird -c \
  "update accounts set domain = 'netbird.selfhosted', domain_category = 'private', is_domain_primary_account = true"
kubectl -n netbird scale deploy server --replicas=1
```

Without it, the first Authentik login creates a second, empty account.

## Account configuration

`netbird_account_settings`: peer network `10.16.0.0/16`, peer DNS domain
`peers.luuk.internal`, JWT group sync off, group propagation on, no user
approval. A `terraform_data` `local-exec`, triggered by the settings resource's
id, deletes the built-in `Default` policy, so only the policies below exist.

| Group | Members |
| --- | --- |
| `admins` | users, assigned by `users.tf` |
| `servers` | headless hosts enrolled with setup key `servers-bootstrap` |
| `kubernetes-api` | the [ClusterProxy](access.md#netbird-clusterproxy) peer |
| `ollama` | the Ollama sidecar peer |
| `printer` | network resource `printer-lan` |

| Policy | Direction |
| --- | --- |
| `admins-to-servers`, `admins-to-kubernetes-api`, `admins-to-ollama`, `admins-to-printer` | `admins` → group only |
| `admins-to-admins` | both ways between admin devices |

The DNS zone `luuk.internal` (search domain enabled) is distributed to `admins`.

OpenTofu owns every group, `admins` included, and its membership. JWT group sync
is off: NetBird never adds JWT members to a group it did not create itself.

### Networks

`networks.tf` declares the network `home-gateway`, for subnets behind the Pi:

| Resource | Address | Group |
| --- | --- | --- |
| `printer-lan` | `10.77.0.0/24`, the [3D printer](../apps/printer.md)'s access point | `printer` |

Its routing peer is not in OpenTofu: in the dashboard, Networks → `home-gateway`
→ add routing peer `home-gateway` with masquerade on. The Pi's NetBird client
forwards to `uap0`; the Pi's firewall lets replies back.

### Users

`users.tf` imports `me@luukblankenstijn.nl` and sets role `admin` and
`auto_groups = [admins]`. The user only exists in NetBird after its first
Authentik login, so the root is applied after that login.

### Setup key

`servers-bootstrap` is reusable, without a usage limit, and puts peers in
`servers`:

```sh
tofu -chdir=terraform/60_netbird-config output -raw servers_setup_key
```

## Operator

`flux/60_netbird-operator` installs netbird-operator into `netbird`,
cluster name `home`, management URL `https://netbird.luukblankenstijn.nl`, API
key from the ExternalSecret `netbird-mgmt-api-key` (`secret/netbird/operator`).
Its webhook has `failurePolicy: Ignore`, so pod admission does not depend on the
operator being up. The layer comes after `apps` because the API key only exists
once NetBird runs.

`flux/70_access` holds the objects that need the operator's CRDs:

- ClusterProxy `home` with its RBAC, see [Cluster access](access.md#netbird-clusterproxy);
- SetupKey `ollama/ollama-sidecar` (ephemeral, extra DNS labels allowed,
  auto-group `ollama`) and SidecarProfile `ollama/ollama`, which injects a
  NetBird sidecar into pods labelled `netbird-peer: ollama` with the extra DNS
  label `ollama`. Ollama has no ingress; its API (port 11434) is reachable only
  over the mesh.

The `access` Kustomization judges SetupKey health by its `Ready` condition only
(see [Flux layers](layers.md#rules)).
